# 五关素材需求推导与生成结果

> 本文档从《新关卡设计方案》**反向推导**每一项素材需求：
> 先说明"这一关的玩法需要玩家看到/听到什么"，
> 再给出对应的素材规格，最后附生成结果。

---

## 一、推导逻辑（为什么是这些素材）

素材不是"看起来该配什么"，而是由**玩法机制反推**出来的。三条推导规则：

| 规则 | 说明 | 例子 |
|---|---|---|
| **机制必须"可读"** | 任何影响玩法的地形/状态，都要有能一眼看懂的视觉表达 | 薄冰格不能种 → 必须有裂纹视觉，让玩家不试就知道 |
| **威胁必须"可预判"** | 会造成损失的机制要给预警期 | 裂隙喷发前 3 秒 → 需要地裂预警贴图 |
| **情绪必须"贴合压力"** | 配乐情绪跟着关卡的难度性质走，不是随便挑好听的 | 信息剥夺关 → 悬疑不安，而非热血 |

## 三、音乐素材清单

### 为什么不是"用 mmx 生成音乐"

实测三条路都走不通，如实记录：

| 方案 | 结果 |
|---|---|
| `mmx music` 子命令 | **不存在** —— mmx 1.0.25 只有 text / speech / image / video / search / vision / file / agent |
| MiniMax 平台 `POST /v1/music_generation` | **HTTP 410**：`This Music API is no longer available to new users` |
| ACE Studio CLI | CLI 已安装，但需要 GUI 常驻（`bridge not reachable`），且以歌声合成为主 |

因此改用**纯 Python 合成管线**（`_gen_music.py`）。
这条路反而更适合本任务：五首曲子的和声走向、配器、情绪都能**精确对齐关卡设计**，
而不是靠 prompt 碰运气。生成后用 ffmpeg 转 160kbps MP3，与游戏现有 BGM 格式一致。

### 五首曲子的设计依据

| 关卡 | 情绪目标 | 调性 / 速度 | 配器 | 时长 |
|---|---|---|---|---|
| **6 霜牙隘口** | 冷冽、疏离、空旷 | A 小调 / 92 BPM | 钟琴主导 + 弦垫 + 稀疏打击 | 41.7s |
| **7 熔心裂谷** | 沉重、压迫、不断逼近 | D 小调 / 120 BPM | 铜管低音 + 十六分贝斯脉冲 + 驱动鼓组 | 32.0s |
| **8 幽影回廊** | 诡异、悬疑、不安 | E 小调（含大七/属七） / 78 BPM | 低频 Drone + 不谐和钟声 + 心跳底鼓 | 49.2s |
| **9 机枢要塞** | 机械、工整、永不停歇 | G 小调 / 132 BPM | 序列琶音 + 金属敲击 + 方波主旋律 | 29.1s |
| **10 星界王座** | 史诗、庄严、终局感 | C 小调 / 108 BPM | 合唱 + 定音鼓 + 弦乐齐奏 + 高频星芒琶音 | 35.6s |

**情绪与难度的对应关系**（这是配乐的核心设计）：
- 关 6 的"冷"对应**规则被剥夺**（击退失效）—— 用空旷留白表达"你失去了依靠"
- 关 7 的"压"对应**阵地会毁**—— 用密集低频脉冲表达"停不下来"
- 关 8 的"悬"对应**信息缺失**—— 用不谐和音程表达"你不知道会发生什么"
- 关 9 的"械"对应**规则约束**—— 用严格循环的序列音表达"必须按规矩来"
- 关 10 的"宏"对应**终局**—— 用合唱与定音鼓表达"这是最后一战"

### 关于素材入库的说明

美术资源目前是 **JPG（16:9 或 1:1）**，而游戏引擎读的是
**BMP 且要求特定尺寸**（草坪 1728×1000、角色方图）。真正接入游戏需要：

1. **抠图**：角色图去掉纯色背景转 alpha（流程见《ai-sprite-asset-pipeline》技能）
2. **缩放对齐**：草坪图缩到 1728×1000，角色图统一到现有精灵的像素高度
3. **格式转换**：PNG(alpha) → 32 位 BMP

这一步是"素材入库"而非"素材设计"。本任务范围是**方案设计 + 素材生成**，
入库所需的尺寸/抠图工序已在此列明，可直接按现有管线执行。
