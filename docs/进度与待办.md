**问题**：短路僵尸切断整行后只显示一条红色指示条，**植物照常工作** ——

- 在**植物逐帧更新循环**里加断电门 —— 放在动画衰减之后、行为分发之前。
  这样断电时植物停止攻击/产阳光/触发肉鸽能力，但受击抖动等表现继续演完
- 选择"在循环里拦一次"而不是"改几十个植物行为分支"，避免漏改和耦合

### ✅ 修掉一个「从未生效」的真实 bug —— flashPrev 顺序错误

冰锥溅射和机械反弹都依赖「这一帧刚被命中」的判定，写法是
`z->flash > 0 && z->flashPrev <= 0`（上升沿）。但 `z->flashPrev = z->flash;`
的赋值**夹在这些检查中间**，等 `newZombieBehavior()` 被调用时，
`flashPrev` 已经等于本帧的 flash 了 —— **上升沿永远检测不到**。

后果：冰锥的溅射、机械僵尸的反弹**从实现那天起就没触发过**
（代码看着有 `case`，实际静默失效）。

**修法**：本帧只算一次 `hitEdge`，显式传给所有消费者，不再依赖语句顺序。

## 五、继续工作时的注意事项

### 1. 断言必须排除「游戏不在战斗状态」

`updateGame()` 只在 `gState == ST_PLAY` 时跑。一旦弹出三选一（`ST_DRAFT`），
**所有计时器一起冻结** —— 这会让「断电冻结了植物」看起来成立，实际是假阳性。

实测踩过：+12s 时进了 DRAFT，计时器停了一段，导致误判「断电没恢复」。
**每步都要断言 `gState == 1`。**

### 2. 测试等待不能超过状态持续时间

冰冻 3 秒而测试等 2.5 秒 → 读到 0，误判「没生效」。
**观察时限状态时要缩短等待**，或者把状态时长调长。

### 3. 测试键要镜像真实路径

`V` 键曾漏调 `bgmForLevel()`，导致「新关卡没音乐」看起来像 bug，实际只是测试键没走完整流程。

### 4. 调试键 `P` 会抢占游戏的暂停键

想测「按 P 暂停」必须改用空格。另外 `B` 键在测试版被「刷僵尸」占用（不是 BGM 开关）。

### 5. 摆植物别依赖 `X` 键

`X` 键在第 9 关会被「必须贴着已有植物种」的连链规则**全部拒绝**（实测 `plants n=0`）。
需要探针植物时直接用 `plantIt(0, 0, PT_SUNFLOWER)`（第 0 列接电源，永远合法）。

### 6. 存档与清理

- 测试脚本**必须**设 `PVZ_SAVE_FILE` 指向副本，否则会改写玩家真档
- `_frames_*` 是测试输出，可随时删；`assets/` 和 `art/raw/` 不可再生
- 当前目录 492 MB（已从 864 MB 清理过）
